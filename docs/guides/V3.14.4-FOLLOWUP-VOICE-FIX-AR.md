# TD AI v3.14.4 — Stable Follow-up Voice Fix

## المشكلة الحقيقية

المهلة كانت تُفحص بعد انتهاء جملة المستخدم.

يعني لو Follow-up Window = 3 ثوان:

1. TD يخلص كلامه.
2. المستخدم يبدأ الكلام بعد ثانية.
3. المستخدم يتكلم 4 ثوان.
4. عند نهاية التسجيل تكون الـ3 ثوان انتهت.
5. الكود يعتبر الجملة غير Follow-up ولا يرد.

كمان Follow-up كان يمر على STT مرة أخرى، وبالتالي أي `no speech` يخلي الرد يضيع.

## الإصلاح

### Follow-up authorization at speech START

الآن إذا بدأت الكلام داخل المهلة، الجملة كلها تعتبر مصرح بها حتى لو استغرقت 10 ثوان.

```text
TD finishes speaking
↓
3-second follow-up window starts
↓
User STARTS speaking inside window
↓
Turn is locked as authorized
↓
User can finish full sentence
↓
Raw audio goes directly to Gemini Live
↓
TD replies
```

### Follow-up bypasses wake STT

بعد أول Wake:

```text
TD
```

الـFollow-up الطبيعي لا يرجع يمر على Wake STT.

هذا يقلل:
- `Gemini STT detected no speech`
- latency
- missed replies

### Sleeping state stays safe

لما TD يرجع Sleeping:
- الكلام العادي لا يذهب إلى Gemini Live.
- Wake STT فقط يحاول اكتشاف `TD`.
- لو STT فشل، يعيد المحاولة مرة بصوت amplified.
- لا يرسل الكلام العادي مباشرة إلى Gemini Live.

### Barge-in

لو نفس الشخص بدأ الكلام قبل ما صوت TD يخلص تمامًا:
- TD يوقف playback.
- الجملة تعتبر Follow-up authorized.
- يسمع المستخدم بدل ما يضيع بداية كلامه.

## Window minimums

حتى لو `voice-control.json` القديم فيه:

```text
1000ms
```

سيتم normalize تلقائيًا إلى:

```text
Wake window: minimum 2000ms
Follow-up window: minimum 3000ms
```

Dashboard ستعرض القيمة الجديدة بعد restart.
