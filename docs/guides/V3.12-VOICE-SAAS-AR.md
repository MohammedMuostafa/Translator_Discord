# TD AI v3.12 — Voice + Usage + Plans Foundation

هذا التحديث مبني فوق تنظيم الريبو الحالي، وكل ملف موجود في مكانه الصحيح داخل `src/` أو `docs/`.

## الموجود في التحديث

### 1) Voice Wake Mode
الوضع الافتراضي للمحادثة الصوتية أصبح Wake Word.

أمثلة:
- `TD`
- `TD AI`
- `Translator`
- `تي دي`
- `يا تي دي`

السلوك:
1. البوت لا يرد على الكلام العادي.
2. لما حد ينادي Wake Word يفتح نافذة قصيرة.
3. يرد على الطلب.
4. يفتح Follow-up Window لمدة افتراضية 3 ثوان.
5. لو محدش كلمه، يرجع Sleeping ولا يرد تاني إلا بعد النداء.

يمكن التحكم في:
- Activation mode
- Wake words
- Wake response
- Wake window
- Follow-up window
- Same speaker / Anyone

من Dashboard → Voice AI.

---

### 2) Voice deterministic commands

تمت إضافة:

```text
/voicechat write
/voicechat skip
/voicechat reconnect
/voicechat usage
/voicechat translate
/voicechat translate-stop
```

أمثلة:

```text
/voicechat write text:Hello everyone
```

أو بالصوت في Wake Mode:

```text
TD اكتب في الشات الاجتماع الساعة تسعة
TD write in the chat GG everyone
TD skip
TD reconnect
TD فاضلي كام في الرصيد
```

`/voicechat write` هو الأمر الأكثر ثباتًا لأنه Host-side Action، ولا يعتمد على أن الموديل "يفهم" إنه لازم يكتب.

---

### 3) Two-way Live Voice Translation

مثال:

```text
English ⇄ Egyptian Arabic
```

شغل:

```text
/voicechat translate
```

واختار:
- Language A
- Language B
- Output
- Quality

Output:
- Voice + Captions
- Voice only
- Captions only

Quality:
- Fast
- Balanced
- Accurate

مهم: أثناء Live Translation، Wake Word لا يُستخدم لأن الترجمة لازم تسمع الطرفين بشكل مستمر.

الـQuality حاليًا تضبط حساسية نهاية الكلام/الـlatency profile:
- Fast: أسرع end-of-speech detection.
- Balanced: وسط.
- Accurate: ينتظر شوية زيادة عشان يقل تقطيع الجمل.

---

### 4) Captions داخل Voice Channel Chat

### 6) الخطط الافتراضية

أثناء الاختبار:

| Plan | Credits / month | Voice AI | Live Translation | Max thinking |
|---|---:|---|---|---|
| Free | 25,000 | Yes | No | Low |
| Plus | 250,000 | Yes | Yes | Medium |
| Pro | 1,500,000 | Yes | Yes | High |

Pro ليست Unlimited.

يمكن تغيير الأرقام من Admin Dashboard بدون Deploy.

الدفع لم يتم ربطه بعد عمدًا. الخطط والاشتراكات جاهزة للإدارة اليدوية، ثم Payment Provider يتربط لاحقًا.

### 7) Dashboard v3.12

أي Discord user يقدر يعمل Login ويشوف:
- Overview

- Plans

الـAdmin فقط يشوف:
- AI Routing

### 8) Provider health + Model failover

Model chain مثال:

```text
gemini-3.7-flash | gemini-3.6-flash | gemini-3.5-flash
```

لو الأول رجع:
- 429
- 503
- 404/unsupported
- transient server error

TD AI ينتقل للـfallback التالي.

Dashboard → Provider Health يعرض:
- healthy
- rate-limited
- busy
- error

مهم:
Provider Health لا يعرض "Gemini quota remaining" بشكل دقيق لأن الرقم المتبقي ليس متاحًا دائمًا من نفس API request.
هو يعرض حالة الـprovider التي شاهدها TD AI فعليًا.

- natural pauses

## Voice Cloning
Voice Cloning الحقيقي ليس مفعّلًا في v3.12 لأن Gemini TTS الحالي في المشروع يعتمد على Voice IDs المتاحة من الـprovider.

لو هنضيف Voice Clone لازم نختار Provider يدعم:
- إنشاء Voice من sample
- Voice ID دائم
- تصريح/موافقة صاحب الصوت

ثم نضيف Adapter منفصل بدون كسر Gemini TTS الحالي.

# Storage

أثناء الاختبار v3.12 يستخدم ملفات داخل `DATA_DIR`:

```text
runtime-config.json
voice-control.json
saas-state.json
```

لازم `DATA_DIR` يكون على Railway Volume لو عايز الإعدادات والـusage تفضل بعد restart/redeploy.

قبل فتح الدفع Public على نطاق كبير، الأفضل نقل:
- users
- subscriptions
- usage
- billing events

إلى PostgreSQL.

الـJSON هنا مناسب للمرحلة الحالية والاختبار، وليس بديل نهائي لقاعدة Billing production متعددة الـinstances.
