# TD AI v3.14.2 — Follow-up Window Timing Fix

## المشكلة

Gemini Live يرسل `turnComplete` عندما ينتهي من **توليد** الصوت.

لكن Discord قد يظل يشغّل الصوت من الـbuffer بعد ذلك.

في النسخة السابقة، `followupWindowMs` كان يبدأ عند `turnComplete`.

مثال مع:

```text
Follow-up window = 1000ms
```

لو بقي في الـDiscord audio buffer ثانية تقريبًا، المهلة تخلص وأنت ما زلت تسمع TD.

لذلك بعد أن ينتهي TD من الكلام، تقول سؤالك ولا يرد.

## الإصلاح

المهلة أصبحت تبدأ فقط عندما يصل Discord Audio Player إلى:

```text
AudioPlayerStatus.Idle
```

أي بعد أن ينتهي الصوت المسموع فعليًا.

المسار:

```text
Gemini turnComplete
↓
Finish output stream
↓
Discord finishes buffered playback
↓
AudioPlayerStatus.Idle
↓
START follow-up window
```

## الإعداد المقترح

داخل Admin → Voice System → Wake Defaults:

```text
Wake window: 3000 ms
Follow-up window: 3000 ms
```

`1000ms` شغالة بعد الإصلاح، لكنها قصيرة جدًا للاستخدام الطبيعي.
